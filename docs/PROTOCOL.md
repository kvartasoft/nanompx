# NanoMPX Protocol Specification

**Status:** normative for NanoMPX protocol version 1  
**License:** this document is published under MIT alongside the reference implementation.

NanoMPX transports a full FM composite (MPX) signal — baseband stereo multiplex including
19 kHz pilot and RDS — over IP. This specification defines the packet format so vendors can
interoperate without linking the reference library.

NanoMPX is **not** compatible with Thimeo MicroMPX.

## Sample format

| Parameter | Value |
|-----------|-------|
| Sample rate | 192000 Hz (fixed) |
| Sample format (API) | signed 24-bit in `int32_t` (sign-extended) |
| PCM wire packing | little-endian 24-bit, 3 bytes per sample |

## Packet layout

Every packet is: **32-byte header** + **payload**.

All multi-byte integer fields are **little-endian**.

### Header (32 bytes)

| Offset | Size | Field | Description |
|--------|------|-------|-------------|
| 0 | 4 | `magic` | `0x58504D4E` (“NMPX”) |
| 4 | 1 | `version` | Protocol version (`1`) |
| 5 | 1 | `mode` | `0` = PCM, `1` = COMPRESSED |
| 6 | 1 | `profile` | `0` PCM; compressed: bitrate in 8 kbps steps (`40` = 320 kbps); `1`–`3` from older encoders |
| 7 | 1 | `flags` | bit0 keyframe, bit1 discontinuity, bit2 FEC |
| 8 | 4 | `seq` | monotonically increasing sequence number |
| 12 | 8 | `sample_index` | index of first sample in this frame |
| 20 | 8 | `capture_time_ns` | capture time of first sample (sample-rate timeline, GPS-tied) |
| 28 | 2 | `payload_len` | payload bytes following header |
| 30 | 2 | `hdr_crc` | CRC-16/CCITT-FALSE over bytes 0–29 (`init=0xFFFF`, poly `0x1021`) |

Receivers **must** drop packets with bad magic, unsupported version, or bad `hdr_crc`.

### Flags

| Bit | Name | Meaning |
|-----|------|---------|
| 0 | KEYFRAME | Independent frame; required after mode/bitrate change |
| 1 | DISCONTINUITY | Timeline break |
| 2 | FEC | Payload is FEC parity (reserved; ignore if unsupported) |

## Modes

### Mode 0 — PCM

Payload is packed s24le mono samples. Length must be a multiple of 3.
Uncompressed payload is 3 bytes per sample (plus packet headers).

### Mode 1 — COMPRESSED

FM band transform codec, payload magic `0xC6` (v6). Reference implementation:
`src/codec_compressed.c`.

| Offset | Size | Field |
|--------|------|-------|
| 0 | 1 | `0xC6` compressed magic (v6) |
| 1 | 1 | bitrate in 8 kbps steps (informative) |
| 2 | 2 | `n_samples` (little-endian) |
| 4 | … | range-coded body (trailing zero bytes may be omitted) |

The body is one range-coder stream (LZMA-style, 32-bit range, carry
propagation). A decoder reads zero bytes past the end of the payload.

1. Pilot: 1 bit `full`. Full (every keyframe, and after a gap in
   `sample_index`): phase u24 (2⁻²⁴ cycle), frequency as signed exp-Golomb of
   the offset from 19 kHz in 2⁻⁴⁰ cycles/sample, amplitude u16 (0.25/65536).
   Otherwise three signed exp-Golomb deltas: phase against the phase predicted
   from the previous packet (`ph + (wq·len + 2¹⁵) >> 16`, exact integers),
   frequency, amplitude.
2. For mono, stereo, RDS I, RDS Q in turn: every MDCT block that the samples
   up to the end of this packet complete. Block `j` of a band covers
   decimated samples `[j·H, j·H + 2H)`; the blocks in a packet are
   `j ∈ [J(sample_index), J(sample_index + n_samples))`,
   `J(x) = ⌊⌈x / dec⌉ / H⌋ − 1`. Per block: a step index per group of bins
   (adaptive-model deltas, step = 2^(−idx/4)), then each coefficient's
   magnitude (adaptive models; context: the two bins below and the same bin
   in the previous block) with a sign bit, and an exp-Golomb escape above 16.
   Models persist across packets and reset on keyframes.

Processing model:

1. A PLL tracks the 19 kHz pilot (θ). The pilot is sent parametrically and
   regenerated by the decoder.
2. Bands, with 577-tap Kaiser-windowed sinc filters at 192 kHz:
   - **Mono** (0–15 kHz): LP 15.75 kHz → decimate ×4 (48 kHz)
   - **Stereo L−R**: ×2 sin(2θ) → same LP → decimate ×4
   - **RDS** (57 kHz ±2.4 kHz): ×2 e^(−j3θ) → LP 2.95 kHz → decimate ×32
     (6 kHz complex, I and Q)
3. Sine-window MDCT: hop H = 512 at 48 kHz (bins coded to 16.5 kHz), 64 at
   6 kHz (bins to 2.6 kHz).
4. Quantiser steps: audio bands are coded for least squared error, one noise
   level per block set relative to the block's power; RDS keeps its noise
   under a floor and below the local signal. The starting targets follow the
   bitrate, and a rate control in the encoder holds it by moving them
   (encoder-only).
5. Decoder: inverse MDCT with overlap-add, matched upsampling filters,
   remodulation with θ, regenerated pilot.

Codec delay: 576 (filters) + 4096 (MDCT) = 4672 samples (24.3 ms).

#### Bitrate

The encoder is set to a bitrate, 128–1024 kbps (`nanompx_encoder_set_bitrate`),
which counts whole NanoMPX packets, the 32-byte header included (26 kbps at
10 ms packets). The decoder needs no setting. The former profiles are
bitrates: L = 320, M = 256, S = 192 kbps (`nanompx_encoder_set_profile`).

Measured band SNR, mono / stereo / RDS in dB, 10 ms packets, steady state
(programme: processed music; synthetic: tones, stereo and RDS test MPX):

| kbps | Programme | Synthetic |
|------|-----------|-----------|
| 160 | 46 / 42 / 23 | 31 / 28 / 24 |
| 192 | 52 / 48 / 23 | 36 / 32 / 24 |
| 256 | 61 / 57 / 24 | 44 / 40 / 25 |
| 320 | 67 / 63 / 27 | 49 / 46 / 28 |
| 384 | 72 / 68 / 29 | 55 / 51 / 30 |
| 512 | 79 / 76 / 34 | 64 / 58 / 36 |

Below about 160 kbps the header and RDS (about 20 kbps) leave too little for
the audio.

Quality should be judged with **band-weighted** metrics (mono/stereo/RDS),
not flat full-MPX waveform SNR, which weights the stop bands the codec
deliberately discards.

The bitrate is in **every** packet header. Changing it requires `KEYFRAME` or `DISCONTINUITY`.

Peak control: decoders must not emit samples whose absolute level exceeds the encoded
frame peak (soft limit). Encoders must not invent overshoots above the source frame peak.

## Transport

NanoMPX packets are transport-agnostic. Recommended mapping:

- **SRT**: one SRT message = one NanoMPX packet
- **UDP**: one datagram = one NanoMPX packet (add FEC/redundancy as needed)
- **File**: concatenation of packets (as produced by the reference CLI)

## SFN timing

`capture_time_ns` is the absolute time of the first sample according to a GPS-disciplined
clock (or equivalent). Decoders play at:

```
playout_time = capture_time_ns + network_delay_ns + user_offset_ns
```

All SFN sites **must** use the same `network_delay_ns`. `user_offset_ns` fine-tunes
interference nulls. Target relative accuracy: **< 1 µs** after GPS lock with matched I/O delay.

See [SFN.md](SFN.md).

## Versioning

- `version` increments on breaking header changes.
- Compressed payload magic/layout may evolve without bumping protocol version
  if old payloads remain decodable.

## Conformance

Reference vectors live under `tests/vectors/`. A conforming implementation must:

1. Accept PCM mode packets and reconstruct bit-exact s24le samples.
2. Parse headers and reject CRC failures.
3. Decode compressed packets of any bitrate produced by the reference encoder (within documented quality).
4. Honor `capture_time_ns` when SFN mode is enabled.
